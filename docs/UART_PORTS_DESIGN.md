# Архитектура многопортового опроса датчиков

## Обзор

MonSet поддерживает три универсальных UART-порта для подключения датчиков (USART3, UART4, UART5). Каждый порт физически имеет два интерфейса — RS-485 и RS-232 — выбор интерфейса задаётся в конфигурации (аппаратного переключателя нет, переключение полностью программное). Каждый порт независимо настраивается, масштабирует данные и ведёт собственный файл резервного копирования.

---

## Назначение UART

| UART    | HAL handle | Пины STM32     | Роль по умолчанию        |
|---------|-----------|----------------|--------------------------|
| USART1  | `huart1`  | PA9 / PA10     | Debug (логи)             |
| USART2  | `huart2`  | PA2 / PA3      | GSM модем A7670C/Air780E |
| **USART3** | **`huart3`** | **PB10 / PB11** | **Датчик порт 0** (дефолт — Modbus RTU, RS-485, DE=PB12) |
| **UART4**  | **`huart4`** | **PC10 / PC11** | **Датчик порт 1** (универсальный) |
| **UART5**  | **`huart5`** | **PC12 / PD2**  | **Датчик порт 2** (универсальный) |
| USART6  | `huart6`  | PC6 / PC7      | ESP8266/ESP32 WiFi       |

## Конфигурация каждого порта

Каждый из трёх датчиковых портов (0, 1, 2) имеет независимую конфигурацию:

### Параметры порта (`UartPortConfig`)

| Поле           | Тип        | Дефолт         | Описание                                      |
|----------------|-----------|----------------|-----------------------------------------------|
| `enabled`      | `bool`    | `true` (порт 0), `false` (1, 2) | Включён ли порт |
| `interface`    | enum      | `RS485`        | Физический интерфейс: `RS485` или `RS232`     |
| `baud`         | `uint32_t`| `9600`         | Скорость: 1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200 |
| `parity`       | enum      | `None`         | Чётность: `None`, `Even`, `Odd`               |
| `stopbits`     | `uint8_t` | `1`            | Стоп-биты: 1 или 2                            |
| `mode`         | enum      | `Modbus_RTU`   | Протокол: только `Modbus_RTU`                 |
| `slave_id`     | `uint8_t` | `1`            | Modbus slave address (1–247)                  |
| `func_code`    | `uint8_t` | `4`            | Modbus function code: 3 (Hold) или 4 (Input)  |
| `start_reg`    | `uint16_t`| `0`            | Начальный регистр                             |
| `num_regs`     | `uint8_t` | `2`            | Количество регистров (1–30)                   |

### Параметры масштабирования (на каждый порт)

| Поле          | Тип     | Дефолт   | Описание                                         |
|---------------|---------|----------|--------------------------------------------------|
| `zero_offset` | `float` | `0.0`    | Вычитается из сырого значения до масштабирования |
| `scale`       | `float` | `1.0`    | Множитель                                        |
| `divider`     | `float` | `1000.0` | Делитель (защита от нуля — авто-фикс на 1.0)     |
| `avg_count`   | `uint8_t`| `1`     | Количество измерений для усреднения (1–100)      |

Формула вычисления значения:

```
value = ((raw - zero_offset) * scale) / divider
```

Усреднение применяется к `raw` до масштабирования: накапливается `avg_count` значений, вычисляется среднее, затем применяется формула.

## Файлы резервного копирования

Каждый порт ведёт **отдельный файл бэкапа** на SD-карте:

| Порт   | Файл бэкапа        |
|--------|--------------------|
| Порт 0 | `backup_p0.jsn`    |
| Порт 1 | `backup_p1.jsn`    |
| Порт 2 | `backup_p2.jsn`    |

Формат файла — JSONL (одна запись на строку), идентичен текущему `backup.jsn`.

### Логика записи в бэкап

- При недоступности сети измерение записывается в файл бэкапа **своего порта**.
- Каждая строка содержит: временну́ю метку, идентификатор порта, сырое и масштабированное значение, метаданные (slave_id, reg).

### Логика отправки бэкапа

При восстановлении связи (`ChMgr` нашёл рабочий канал) выполняется последовательный перебор файлов:

```
1. Открыть backup_p0.jsn — если непустой, отправить построчно
2. Открыть backup_p1.jsn — если непустой, отправить построчно  
3. Открыть backup_p2.jsn — если непустой, отправить построчно
4. После успешной отправки строки — удалить её из файла (или пометить)
5. После опустошения файла — удалить файл
```

Порядок фиксированный (0 → 1 → 2). Если отправка прервалась — возобновляется с того же места при следующем цикле (позиция не сохраняется — файл перечитывается с начала, уже отправленные строки удалены).

## Веб-интерфейс

В разделе **"Порты датчиков"** для каждого из трёх портов отдельная карточка настройки:

- Включить/выключить порт (`enabled`)
- Выбор интерфейса: RS-485 / RS-232 (radio button)
- Параметры UART: baudrate, parity, stopbits
- Параметры Modbus: slave ID, function code, start reg, num regs
- Параметры масштабирования: zero offset, scale, divider, avg count
- Статус: последнее измерение, время, ошибки

---

## Дефолты порта 0 (USART3, обратная совместимость)

Порт 0 наследует текущую конфигурацию `modbus_slave / modbus_func / modbus_start_reg / modbus_num_regs / sensor_zero_level / sensor_divider / avg_count` из существующего конфига. При первом запуске новой прошивки эти поля мигрируют в `ports[0]` автоматически через `setDefaultsFromConfig()`.

Глобальные поля `modbus_slave`, `sensor_divider` и т.д. остаются в `RuntimeConfig` как deprecated — читаются для обратной совместимости, но при сохранении конфига с новым веб-интерфейсом заменяются структурой `ports[]`.
